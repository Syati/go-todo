# Rails 版からの移植判断

Go 版で確認した利用フローでは、特権管理者が管理者アカウントを作成し、担当者がブラウザーからログインして商品と SKU を管理します。ログイン不能時は、別の特権管理者による変更か、承認された運用担当者による [単独の特権管理者の復旧](admin-recovery.md) を使います。

| 機能 | 判断 | 現時点の根拠 | 再検討する条件 |
| --- | --- | --- | --- |
| OAuth / OmniAuth | 保留 | Rails のルートは `developer` プロバイダーを登録しています。Go 版で確認したフローはメールアドレスとパスワードで完結します。 | 本番で利用する IdP、必須のログイン方式、既存アカウントとの紐づけ要件が決まったとき。 |
| JSON API | 保留 | Rails の確認対象のルートに JSON 専用 API の経路はなく、Go 版で確認した商品・SKU 操作も管理画面から行います。 | 連携先、公開する操作とデータ、認証要件が明確になったとき。 |
| メール確認 | 保留 | Rails は Devise の `confirmable` を利用します。Go 版は特権管理者がアカウントを作る方式なので、確認済みの利用フローに公開登録や招待リンクはありません。 | 招待の受諾時にメールの所有を確認する必要が生じたとき。 |
| メールによるパスワード再設定 | 保留 | Rails は Devise の `recoverable` を利用します。Go 版には管理画面からの変更と単独の特権管理者の復旧手順があります。 | 担当者が運用対応を待たずに自分で復旧する要件や、復旧までの目標時間が決まったとき。 |

採用条件が確認できた機能は、対象の利用者・利用フロー・受け入れ条件を個別の GitHub Issue に記録します。今回の判断は確認できたリポジトリの実装とブラウザーの動作に基づきます。

参照した Rails の実装は [ルート定義](https://github.com/Syati/rails8-todo/blob/75013ec7ac99777c6481b46e91ed3519c5cbd27e/config/routes.rb) と [管理者モデル](https://github.com/Syati/rails8-todo/blob/75013ec7ac99777c6481b46e91ed3519c5cbd27e/app/models/admin.rb) です。
